# Memory-mapped circular log

`output.exe` keeps a fixed-size, memory-mapped circular log on disk. The log is a
single file, `output.log`, of constant size **1 MB** (`100000h` = 1,048,576
bytes). All logging code is generated by `main.c` through the `write_*` helpers
in `asm_funcs.h`; nothing is hand-written assembly. Building always goes through
`build.bat` (compile `main.c` → run it to emit `output.asm` → assemble → link).
The build's working directory is `out/`, so `output.asm`, `output.exe`, and
`output.log` are created there. The program itself still opens `output.log`
in whatever directory it was started from.

## Lifecycle

The first thing `main` does, before any logging, is set up the mapping:

1. **Open + truncate the file**

   ```
   CreateFileA("output.log", GENERIC_READ|GENERIC_WRITE, 0, NULL,
               CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL)
   ```

   `CREATE_ALWAYS` creates the file if it is missing and **truncates it to zero
   length if it already exists**, so every launch starts from an empty buffer.

2. **Create a 1 MB mapping**

   ```
   CreateFileMappingA(hFile, NULL, PAGE_READWRITE, 0, LOG_SIZE, NULL)
   ```

   Passing `LOG_SIZE` (`100000h`) as the maximum size **grows the backing file to
   exactly 1 MB**. The newly extended region is guaranteed zero-filled by the OS,
   so no separate `SetFilePointer`/`SetEndOfFile` is needed and the buffer always
   starts clean.

3. **Map the whole view**

   ```
   MapViewOfFile(hMap, FILE_MAP_ALL_ACCESS, 0, 0, 0)
   ```

   A `dwNumberOfBytesToMap` of `0` maps the entire 1 MB section. The returned
   base address is stored in `pView`; from then on the mapped memory *is* the log
   file — writes to `[pView + offset]` land directly in `output.log`.

After mapping, the write head `logPos` is reset to `0` and logging can begin.

## Circular-buffer semantics

The entire 1 MB view is one ring. `logPos` is the in-memory write head, an offset
in `0 .. LOG_SIZE-1`. `logPos` lives in `.data?` and resets to `0` each run, so a
fresh run begins writing at offset 0. To append a record of `len` bytes from
`src`:

1. **Clamp:** a record longer than `LOG_SIZE` is truncated to `LOG_SIZE`, so a
   single append can never run past the mapped region.
2. **Fits before the end** (`len <= LOG_SIZE - logPos`): copy `len` bytes at
   `pView + logPos`, then advance `logPos += len`, wrapping to `0` if it reaches
   `LOG_SIZE`.
3. **Wraps past the end** (`len > LOG_SIZE - logPos`): copy the tail portion
   (`space = LOG_SIZE - logPos` bytes) at `pView + logPos`, then copy the
   remaining `len - space` bytes starting at `pView + 0`, and set
   `logPos = len - space`.

This makes the log a true wrap-around ring: old data at the start of the buffer
is overwritten once the head wraps, and a write is never split incorrectly or
allowed to overflow the 1 MB region.

> The head is **not** persisted. Because the file is truncated on startup and
> `logPos` starts at 0, the log does not resume across runs — each launch is a
> fresh, empty 1 MB buffer.

## Implementation

### Data

Emitted into the data segments of `output.asm`:

```
LOG_SIZE equ 100000h          ; 1 MB, the whole ring

.data
logName    db "output.log",0  ; file name passed to CreateFileA
msgStarted db "started",10    ; demo record written at startup
msgStartedLen equ $ - msgStarted

.data?
hFile  dq ?                   ; file handle from CreateFileA
hMap   dq ?                   ; mapping handle from CreateFileMappingA
pView  dq ?                   ; base address of the mapped 1 MB view
logPos dq ?                   ; current ring write head (in-memory)
```

### The `log_write` routine

`log_write` takes `rcx = source pointer` and `rdx = byte count` and performs the
clamp/copy/wrap logic above using `rep movsb`. It only touches volatile
registers, so callers need not preserve anything across it:

```
log_write proc
    cld                       ; forward string moves
    cmp rdx, LOG_SIZE         ; clamp len to at most the buffer size
    jbe lw_size_ok
    mov rdx, LOG_SIZE
lw_size_ok:
    mov rsi, rcx              ; rsi = src
    mov r8,  rdx              ; r8  = len
    mov r9,  logPos           ; r9  = head
    mov rdi, pView
    add rdi, r9               ; rdi = pView + head
    mov r10, LOG_SIZE
    sub r10, r9               ; r10 = space until end of buffer
    cmp r8, r10
    jbe lw_single             ; fits before the end?
    ; --- wrap: tail chunk, then remainder at the base ---
    mov rcx, r10
    rep movsb
    mov rdi, pView
    mov rcx, r8
    sub rcx, r10
    rep movsb
    mov r9, r8
    sub r9, r10               ; new head = len - space
    mov logPos, r9
    ret
lw_single:
    mov rcx, r8
    rep movsb
    add r9, r8                ; head += len
    cmp r9, LOG_SIZE
    jb  lw_store
    sub r9, LOG_SIZE          ; wrap (head == LOG_SIZE -> 0)
lw_store:
    mov logPos, r9
    ret
log_write endp
```

To log a record, load the source address and length and call it, e.g. the
startup demo:

```
lea rcx, msgStarted
mov rdx, msgStartedLen
call log_write
```

### Supporting framework details

The external Win32 calls are declared with the `write_common_extern*` helpers
(x64 Windows integer convention: arguments in `rcx, rdx, r8, r9` then the stack,
result in `rax`) and emitted with `write_call`, which lays out shadow space,
places 5th+ arguments at `[rsp+32]`…, and keeps `rsp` 16-byte aligned at the call
regardless of argument count. `CreateFileA` (7 args), `CreateFileMappingA`
(6 args) and `MapViewOfFile` (5 args) all exercise the stack-argument path.

## Inspecting the log

`output.exe` is a `/subsystem:windows` binary, so a plain shell run does not
surface its exit code; from `out/`, use `Start-Process .\output.exe -Wait -PassThru`
to read it. After a run, `output.log` in that directory is exactly 1,048,576
bytes, begins with the logged records (`started\n` for the default build), and
is zero-filled beyond the head.
